\chapter{AI driven penetration testing}
\label{ch:chapter05}
Earlier approaches to automate the process of penetration testing like ESA's PenBox leveraged Reinforcement Learning. PenBox has the capability to execute given actions like port scanning with NMap, SSH security testing with Hydra and exploitation of known vulnerabilities with Metasploit. Training landscapes were built to train PenBox to use the given actions beneficially. PenBox's training and test environment comprises 8 hosts in one network. In this rather small environment PenBox was able to compromise vulnerable hosts with 33 actions taken while the minimal requires actions would have been 4. \cite{Confido_2022}

Leveraging \ac{LLM}s for penetration testing shows better results and scalability in comparison to Reinforcement Learning. \ac{CTF} Challenges from HackTheBox and VulnHub were used to evaluate the performance of GPT-4 without any technical additions. GPT-4 was prompted to advice the user to execute a specific task like running a \ac{CLI} command which's output the user prompts back to the \ac{LLM}. Such a technically minimalistic setup proves that \ac{LLM}s are capable of performing penetration tests as GPT-4 is able to solve 4 easy and 1 medium challenge. This benchmark was executed on 13 targets from HackTheBox and VulnHub covering OWASP Top 10 and categories easy, medium and hard. The available knowledge was entirely limited to the \ac{LLM}s inherit domain knowledge. \cite{Deng_2024}

The process of penetration testing can be split up into multiple tasks which allows to deligate different tasks to different \ac{LLM} agents that are specialized in certain fields. The architecture of PentestGPT introduces three agents to delegate these tasks to. One agent responsible for information condensing, one for reasoning and one for concrete task planing. This agentic approach further improves the \ac{CTF} challenge completion rate. Without the agentic approach GPT-4 was able to solve 4 easy and 1 medium challenge, with the agentic setup it is able to solve 6 easy and 2 medium challenges out of the same set of challenge. The increase in \ac{CTF} challenge completion rate points to the significance of the \ac{LLM} orchestration. \cite{Deng_2024}

One limiting factor towards higher \ac{CTF} challenge completion is the lack of up-to-date domain specific knowledge such as known vulnerabilities. The knowledge of an \ac{LLM} is entangled within thousands of parameters. Retraining \ac{LLM}s with up-to-date information is computationally very expensive. \ac{RAG} introduced by Lewis et al. \cite{lewis_2020} is a common approach to provide \ac{LLM}s with knowledge it has not inertly build in. The additional information are stored as embeddings in a vector database. The \ac{LLM} is then provided with retrieved information from the \ac{RAG}'s vector database. \cite{lewis_2020}

PentestAgent improves the architecture of PentestGPT by introducing domain specific knowledge on known vulnerabilities. It equips the agentic setup with a \ac{RAG}. This external knowledge base makes multiple vulnerability databases accessible for PentestAgent. Through several adjustments regarding the agentic setup and the additionally introduces domain specific knowledge PentestAgent outperforms PentestGPT by far when it comes to solving \ac{CTF} challenges. 11 \ac{CTF} challenges were randomly selected from HackTheBox (nine easy, one medium and one hard). PentestGPT was able to solve 5 of these challenges (all easy) while PentestAgent was able to solve 9 of these challenge (7 easy, one medium and one hard). \cite{Shen_2025}

The success of PentestGPT and PentestAgent are not limited to small networks or even single hosts. \ac{AI} Agents and thus \ac{LLM}s are also capable of performing penetration tests in real world and real size networks. ARTEMIS is an agentic approach like PentestGPT and PentestAgent. However it was optimized and tested in a real world university network. Two versions of ARTEMIS were benchmarked against experienced human penetration testers. The first ARTEMIS version running entirely on GPT-5 came up with 11 findings out of which 55\% were valid findings. The second ARTEMIS version running on multiple different \ac{LLM}s was able to come up with 11 findings as well. However, 82\% of them were valid. Also their severity was much higher. Both versions are able to compete with human penetration testers. The architects of ARTEMIS mention that the agents scans systems in a broad manner instead of moving lateral like experience human penetration testers do. By moving lateral human penetration testers tend to make findings with higher severities. \cite{Lin_2025}

Real world corporate applications are much more complicated and unknown than test environments like DVWA, OWASP Juice Shop, OWASP WebGoat and many \ac{CTF} challenges. They have dynamic pages with JavaScript logic and proprietary, sometimes niche technology stacks. Automated testing tools need to traverse the detailed architecture of the system under test. XBOW is a \ac{LLM} powered automated penetration testing tool that publicly claims to be able to work with corporate applications and all its challenges. XBOW can operate with and without access to the source code of the system under test. \cite{xbow2026} Not many information about the detailed system structure are made public. XBOW's high position on the Hackerone leaderboard however proves that it is clearly capable of making valid findings in corporate infrastructure. \cite{hackerone_leaderboard} \cite{xbow_hype}

Corporate security experts who used XBOW on proprietary web applications shared their experiences for this term paper. To evaluate XBOW's performance, the corporate security experts used a deliberately vulnerable web application based on a proprietary technology stack as a benchmark system. The experts found that XBOW was unable to identify any vulnerabilities in this system. XBOW was provided with source code and network access to the application. According to the experts, XBOW is capable of finding vulnerabilities in other applications, but they report that the tool tends to produce a high rate of false positives. The experts also note that valid findings made by XBOW are generally low-hanging fruits from the perspective of experienced penetration testers.

Software vendors like Google implement \ac{LLM} powered penetration testing tools into software security processes. Google's open-source oss-fuzz for example is a \ac{LLM} powered fuzzing tool that actively found many security flaws in open source software. \cite{Happe_2025}

\section{Security Challenges}
\label{sec:chapter05:sec_challenges}
\ac{LLM}s are trained based on a set of data. Those datasets do not encompass the entirety of available information. As not even the entirety of information necessarily represents truth, \ac{LLM}s have inherit bias from their training data. This can lead to unwanted treatment of actual vulnerabilities. A biased \ac{LLM} can potentially overlook vulnerabilities. \cite{Hilario_2024}

In the context of penetration testing \ac{LLM}s are often times equipped with tools like web search. Prompts can be injected into the \ac{LLM}'s context through the access of third party webpages. In the combination with the \ac{LLM} holding confidential data, the risk of leaking these information to a third party webpage rises.
