\chapter{Discussion}
\label{ch:chapter06}

The vulnerabilities that PentestGPT, PentestAgent and ARTEMIS exploited in the benchmarks are nearly all performed based on known vulnerabilities or in controlled and unrealistic test environments. For cooperate vendors especially web application penetration testing is highly interesting. This is because web applications are highly exposed and popular. Especially PentestAgent targets at exploiting known vulnerabilities instead of investigating architecture of web applications to find new vulnerabilities. For finding new vulnerabilities in unknown web applications these tools are not made and tested for.

PentestGPT's performance was evaluated based on 13 \ac{CTF} challenges and PentestAgent's performance based on 11 \ac{CTF} challenges which is even less. The process of choosing these challenges is opaque. PentestGPT was evaluated on hand picket challenges and PentestAgent based on randomly selected once. Both selecting processes can influence the evaluation result.

Corporate \ac{LLM} driven penetration testing tools like XBOW and oss-fuzz clearly show that \ac{LLM}s are capable of finding security vulnerabilities in corporate software.

When it comes to proprietary technology stacks that may even use niche frameworks XBOW reaches it's limits digging deep enough into the inner workings of proprietary code bases. The security expert who conducted tests on XBOW conclude that XBOW lacks the capability of lateral movement required to thoroughly investigate the working principles of the applications under test.
